# Phase 6: op1.fun Integration Implementation Plan

**Status: complete (2026-10-29).** All six tasks are implemented on `main`. Review established that op1.fun's S3 bucket sends no CORS headers, so installs always go through the Worker file proxy and are disabled (with the reason shown) when the build has no Worker URL. Differences from the text below: the file proxy accepts only op1.fun, www.op1.fun and the `op1fun` bucket's hosts (virtual-hosted or path style, any region) and only `.aif`, `.aiff` and `.mp3`, refuses upstream redirects (`redirect: 'manual'`), counts the 20 MB cap while streaming, and answers with an audio-only Content-Type, `Content-Disposition: attachment` and a sandboxing CSP; the upload route refuses redirects, caps the body at 13 MiB while streaming and forwards only the two credential headers and `Content-Type`; the op1.fun routes use their own `OP1FUN_LIMIT` binding (60 a minute per client, keys `op1fun-upload:` and `op1fun-file:`) because the feedback limit (5 a minute) is too low for pack installs through the proxy; the client refuses uploads over 9 MiB or with descriptions over 2000 characters, times uploads out after 65 s and keeps only https links from the API; installs run inside `device.run` with the Packs tab's source-key check, take the kind from the file (falling back to op1.fun's patch type), and install pack patches one by one from `included`; the Upload action is always shown but disabled, with its reason shown once above the table, when there is no Worker URL or no credentials; the e2e build has a test-only `VITE_WORKER_URL` answered by `page.route` and is built into `web/dist-e2e` so it can never be deployed. The spec's sections 3, 5.4 and 7 and `docs/deploying-the-worker.md` are the reference.

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A user enters their op1.fun email and API token, browses their own and other users' patches and packs, previews them, installs them onto their OP-1, and uploads patches from their device to their op1.fun account.

**Facts:** API base `https://api.op1.fun/v1`, JSON:API-style responses, auth headers `X-User-Email` and `X-User-Token` on every request. Verified on 2026-10-28 with curl: preflight allows `GET, OPTIONS` with those two headers from any origin, so reads go direct from the browser; POST is not allowed cross-origin, so uploads go through the Worker. Endpoints: `GET /users/:username`, `GET /users/:username/patches`, `GET /users/:username/patches/:id`, `GET /users/:username/packs`, `GET /users/:username/packs/:id` (with `included` patches), `GET /users/:username/packs/:id/download` (returns `{ url }`, slow, 60 s timeout), `POST /patches` with `{ data: { type: 'patches', attributes: { name, public, description, license, file: 'data:audio/x-aiff;base64,...' } } }`, licences blank or `CC BY`, `CC BY-SA`, `CC BY-NC`, `CC BY-ND`. Patch `links.file` (AIFF) and `links.preview` (MP3) point at S3; whether S3 allows CORS `fetch` is unverified because every listing needs credentials. Pagination and search are undocumented.

**Architecture:** `web/src/core/op1fun/` holds a typed client (fetch injected), response mappers into plain types, and an install helper reusing the catalogue install path (raw bytes, writeAtomic, freeName). Files are fetched directly first; on a network/CORS failure the client retries through the Worker's `GET /op1fun/file?url=` proxy (host-allowlisted). Uploads go to the Worker's `POST /op1fun/patches`, which forwards the caller's headers and body unchanged and stores nothing. Credentials live in memory by default; "Remember on this device" stores them in localStorage.

### Task 1: client and mappers

`web/src/core/op1fun/types.ts`: `Op1FunCredentials { email; token }`, `Op1FunPatch { id; name; description; license; public; patchType; fileUrl; previewUrl; userId }`, `Op1FunPack { id; name; description; public; patchIds; downloadUrl }`, `Op1FunUser { id; username; patchIds; packIds }`.

`client.ts`: `class Op1FunClient { constructor(creds, opts: { fetch?: typeof fetch; base?: string; workerUrl?: string }) }` with `getUser(username)`, `listPatches(username)`, `getPatch(username, id)`, `listPacks(username)`, `getPack(username, id): Promise<{ pack; patches }>`, `requestPackZip(username, id)` (AbortSignal timeout 65 s), `fetchFile(url): Promise<Uint8Array>` (direct, then Worker proxy on `TypeError`; throws `Op1FunError` when neither works, with a message saying the Worker is needed), `uploadPatch({ name, description, license, public, bytes })` (builds the data URI, POSTs to `${workerUrl}/op1fun/patches`; throws `Op1FunError('uploads need the co-op Worker')` when no workerUrl). Map 401 to `Op1FunAuthError`. Defensive mapping: missing optional attributes become empty strings/false; unknown shapes throw `Op1FunError('unexpected response')`. Base64 encode in chunks (no spread of large arrays). The create response wraps the patch in an array; accept both shapes.

Tests with a fake fetch covering every method, auth headers present on API calls and absent on S3 file fetches, the CORS fallback, 401 mapping, both create-response shapes, and base64 of the real drum fixture round-tripping. Commit `feat(op1fun): typed API client`.

### Task 2: Worker routes

- `POST /op1fun/patches`: requires `X-User-Email` and `X-User-Token`; body JSON max 12 MB (base64 of a 9 MB file); validates `data.type === 'patches'` and that `attributes.file` starts with `data:audio/x-aiff;base64,`; forwards to `https://api.op1.fun/v1/patches` with only those two headers plus `Content-Type: application/json`; returns upstream status and body unchanged with CORS headers. Never logs.
- `GET /op1fun/file?url=`: only `https:` URLs whose host ends with `.amazonaws.com` or equals `op1.fun`/`www.op1.fun` and whose path ends in `.aif`, `.aiff` or `.mp3` (case-insensitive); streams the upstream body with `Content-Type` passed through, max 20 MB (abort beyond); 400 otherwise. Shares the rate limiter with a separate key prefix.
- Tests with mocked fetch for both routes, including rejected hosts (`evil.com`, `amazonaws.com.evil.com`, `http:`), oversize bodies and header forwarding. Commit `feat(worker): op1.fun upload and file proxy`.
